# 首页轮播图 + 公告栏 · 排版方案

> 视觉稿：`01-home-layout.png`、`02-notice-flow.png`
> 可交互查看：`preview.html?view=home` / `preview.html?view=notice`

## 一、推荐结构

首页从上到下保持现有顺序，只在「搜索框」和「订单列表」之间插入两块内容：

```
状态栏 / 原生导航（首页）
取件 / 取餐 + 搜索框        ← 保持不动
────────────────────────
轮播图                      ← 新增
公告条 + 公告中心入口        ← 新增
待接订单（小标题 + 列表）    ← 原有列表顺延
────────────────────────
悬浮发布按钮 / 底部导航      ← 保持不动
```

选择这个位置的原因：

1. 取件 / 取餐和搜索是首页的主功能，不能被轮播压到第二屏。
2. 轮播和公告属于「内容发现」，放在功能区之后、列表之前，符合浏览顺序。
3. 新增区域约 **232px**，首屏仍能完整看到 **2 张订单卡片**，不会把列表挤没。
4. 轮播不参与取件 / 取餐切换，切换类型时不会闪动。

## 二、尺寸与样式

| 元素 | 建议尺寸 | 说明 |
| --- | --- | --- |
| 页面左右留白 | 16px（32rpx） | 与现有搜索框、卡片一致 |
| 轮播图 | 686 × 272rpx（343 × 136px） | 圆角 14px，占满内容宽 |
| 轮播圆点 | 4px，当前项拉长 14px | 白色半透明，叠在图片底部 |
| 公告条 | 高 46px，圆角 12px | 白底，左右 16px 留白 |
| 公告条图标 | 28 × 28px 浅绿底圆角 | 喇叭图标 |
| 公告中心按钮 | 图标 14px + 文字 11.5px | 右侧常驻，未读时铃铛带红点 |
| 列表小标题 | 12.5px，绿色竖条 3 × 12px | 可选，用来隔开公告和卡片 |
| 弹窗 | 宽 322px，圆角 20px | 屏幕水平居中 |

轮播图建议 **3–5 张**，4 秒自动切换，循环播放；只有 1 张时关闭自动播放并隐藏圆点。

## 三、轮播图

### 内容类型

同一套轮播位可以混排：

- **公告**：跳公告详情，适合重要通知。
- **活动**：跳活动页 / 专题页。
- **广告**：跳站内页面、H5 或其它小程序。

### 点击跳转

每张单独配置，不写死在代码里：

```js
{
  id: 'banner-01',
  imageUrl: 'https://.../banner-01.png',
  tag: '公告',              // 公告 / 活动 / 广告
  title: '国庆取件时间调整',
  subtitle: '10 月 1 日 – 3 日 · 09:00–18:00',
  linkType: 'notice',       // notice / page / web / miniProgram / none
  linkValue: 'notice-20260928'
}
```

- `notice`：打开公告详情，并写入已读。
- `page`：`wx.navigateTo` 到站内页面。
- `web`：打开 `web-view` 页，需要配置业务域名。
- `miniProgram`：`wx.navigateToMiniProgram`，需要目标 appId 和后台配置。
- `none`：只展示，不跳转。

没有图片或图片加载失败时，用品牌绿渐变 + 标题兜底，不要留白块。

## 四、公告条与公告中心

### 公告条

- 显示**最新一条已发布公告**的标题，单行省略。
- 左侧喇叭图标，右侧「公告中心 ›」入口。
- 点击标题区：进入最新公告详情。
- 点击「公告中心」：进入公告列表。
- 没有公告时显示「暂无公告」，入口保留，不显示红点。

### 公告中心

- 顶部筛选：全部 / 未读 / 系统（可扩展活动）。
- 未读公告：标题前红点、标题加粗、卡片白底。
- 已读公告：标题变灰、去掉红点。
- 支持置顶、分类标签（系统公告 / 活动 / 置顶）。
- 右上角「全部已读」。
- 列表按发布时间倒序，支持分页或下拉刷新。

### 小红点

- 数据来源：服务端返回的未读公告数 `unreadCount`。
- 位置：「公告中心」按钮的铃铛右上角。
- 进入公告中心并读完，或点击「全部已读」后，红点立即消失。
- 不在底部导航「首页」上再加红点，避免和公告入口重复。

## 五、登录后强制阅读弹窗

### 触发条件

1. 登录成功，进入首页。
2. 服务端存在**未读且需要强提醒**的公告。
3. 同一账号、同一条公告没有自动弹过。

三个条件同时满足才弹，避免每次进首页都打扰。

### 展示内容

- 顶部喇叭图标 + 「重要」标签 + 「系统公告 · 发布时间」。
- 公告标题（最多两行）。
- 正文区域，超出高度可滚动，不截断内容。
- 底部倒计时按钮 + 进度条。

### 5 秒规则

- 弹窗出现即开始倒计时，按钮为灰色，文案「5 秒后可关闭」。
- 5 秒内：点击遮罩、点空白、返回都无效，只更新倒计时数字。
- 5 秒后：按钮变绿，文案「我已阅读」，点击关闭。
- 关闭时调用已读接口，公告中心红点同步消失。
- 切到后台再回来，用「截止时间 - 当前时间」续算，不重新开始。
- 同一条公告只自动弹一次；后续可在公告中心主动查看。

### 边界说明

- 5 秒限制是**页面内的界面约束**，用户仍然可以通过系统返回、杀掉小程序绕过；服务端只记录「阅读完成」，不能强制用户停留。
- 自定义弹窗覆盖不了微信原生导航栏和状态栏，所以视觉稿里顶部绿色导航仍然可见，这是正常现象。
- 如果公告很长，正文区域内部滚动；5 秒是「最短停留」，不是「读完」的保证。

## 六、接口与数据建议

### 轮播

```http
GET /api/banners?position=home
```

返回字段：`id / imageUrl / tag / title / subtitle / linkType / linkValue / sort / startAt / endAt`。

### 公告列表

```http
GET /api/announcements?page=1&size=20&filter=all|unread
```

返回字段：`id / title / summary / content / level / category / pinned / publishedAt / read`。

### 未读数

```http
GET /api/announcements/unread-count
```

### 标记已读

```http
POST /api/announcements/{id}/read
```

### 强制弹窗用

```http
GET /api/announcements/pending
```

返回当前账号需要自动弹出的公告（没有则返回 `null`）。建议由服务端判断「未读 + 需要强提醒 + 未弹过」，前端只负责展示。

## 七、实施顺序（确认排版后）

1. 首页 WXML / WXSS：插入轮播、公告条、公告中心入口。
2. 首页 JS：加载轮播和公告数据，接上跳转、红点、弹窗触发。
3. 新增公告中心页 + 公告详情页（或详情弹层）。
4. 后端：轮播表、公告表、已读表，以及对应接口。
5. 联调：登录后弹窗、5 秒倒计时、红点消失、轮播跳转、空数据兜底。

## 八、需要确认的点

3. 公告条是显示「最新一条」，还是做上下滚动的多条公告？
4. 这次只做前端（先用本地假数据看效果），还是前后端一起做？
